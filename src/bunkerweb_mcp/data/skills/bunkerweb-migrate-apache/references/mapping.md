# Mapping: Apache httpd to BunkerWeb

Verified at BunkerWeb v1.6.15 for every BunkerWeb name. Directive names are Apache's: check them against the user's httpd version (`ProxyPass ... upgrade=websocket` needs 2.4.47 or later, older builds use `ws://` with `mod_proxy_wstunnel`). Per-service settings are `<server_name>_<SETTING>` with `MULTISITE=yes`, or `bunkerweb.<SETTING>` labels with autoconf. The [`bunkerweb-migrate-nginx`](https://github.com/bunkerity/bunkerweb-skills/tree/main/skills/bunkerweb-migrate-nginx) skill maps the shared settings in more detail.

## Mapping

| Apache                                             | BunkerWeb                                                                                                         | Notes                                                                                                                                                                                                                                                                                            |
| -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `<VirtualHost>`, `ServerName`, `ServerAlias`       | `SERVER_NAME`                                                                                                     | One entry per name, space-separated. The first is the multisite prefix. Apache serves any unknown `Host` from its first vhost; see the traps.                                                                                                                                                    |
| `Listen 80` / `Listen 443`                         | published ports `80:8080` and `443:8443`                                                                          | BunkerWeb listens on 8080 and 8443 inside its container.                                                                                                                                                                                                                                         |
| `ProxyPass "/" "http://host:port/"`                | `USE_REVERSE_PROXY=yes`, `REVERSE_PROXY_HOST=http://host:port`                                                    | Scheme required, no path after the port.                                                                                                                                                                                                                                                         |
| `ProxyPass "/app" "http://host/"`, `<Location>`    | numbered `REVERSE_PROXY_URL_<n>` and `REVERSE_PROXY_HOST_<n>`                                                     | One pair per proxied path. A path inside `REVERSE_PROXY_HOST` replaces the whole URI, so strip a prefix with a regex `REVERSE_PROXY_URL_<n>` and use its capture plus `$is_args$args` in `REVERSE_PROXY_HOST_<n>`. Test bare paths and encoded characters; in compose, write each `$` as `$$`.   |
| `ProxyPassReverse`                                 | no setting                                                                                                        | The generated config has no `proxy_redirect`, so an upstream `Location` or `Set-Cookie` that names the backend host passes through unchanged. Check them in the detect run.                                                                                                                      |
| `ProxyPreserveHost On`                             | default                                                                                                           | BunkerWeb sends the client's `Host` and `X-Forwarded-Host`. Apache's own default (`Off`) sends the backend name: set `REVERSE_PROXY_CUSTOM_HOST` if the app relies on that.                                                                                                                      |
| websocket, `upgrade=websocket` or `ws://`          | `REVERSE_PROXY_WS_<n>=yes` on the websocket location                                                              | Per location. It adds the upgrade headers.                                                                                                                                                                                                                                                       |
| `RequestHeader set Name value`                     | `REVERSE_PROXY_HEADERS[_n]=Name value;Other value`                                                                | Per location. Defaults sent without any setting: `Host`, `X-Forwarded-For`, `X-Real-IP`, `X-Forwarded-Proto`, `X-Forwarded-Protocol`, `X-Forwarded-Host`, and `X-Forwarded-Prefix` for a non-regex URL that starts with `/`.                                                                     |
| `Header always set Strict-Transport-Security ...`  | `STRICT_TRANSPORT_SECURITY=max-age=31536000; includeSubDomains`                                                   | Sent on HTTPS responses only; Apache's `always` also sends it on HTTP. The default is `max-age=63072000; includeSubDomains; preload`, so set your own value.                                                                                                                                     |
| `Header set` for CSP, frame, referrer, permissions | `CONTENT_SECURITY_POLICY`, `X_FRAME_OPTIONS`, `REFERRER_POLICY`, `PERMISSIONS_POLICY`, `X_CONTENT_TYPE_OPTIONS`   | All ship with non-empty defaults. Any other response header: `CUSTOM_HEADER_<n>=Name: value`.                                                                                                                                                                                                    |
| `Header unset Server`, `ServerTokens Prod`         | `REMOVE_HEADERS`                                                                                                  | The default already strips `Server`, `X-Powered-By` and a few more.                                                                                                                                                                                                                              |
| `LimitRequestBody 5242880`                         | `MAX_CLIENT_SIZE=5m` (default `10m`); one location: `REVERSE_PROXY_MAX_CLIENT_SIZE[_n]`                           | Bytes become `k`/`m`/`g`. Over the limit gives 413. See the first trap: Apache did not enforce the old limit on proxied bodies.                                                                                                                                                                  |
| `Require ip 10.0.0.0/8` on one `<Location>`        | a numbered entry plus `REVERSE_PROXY_INCLUDES_<n>=/path/acl.conf` holding `allow 10.0.0.0/8;` and `deny all;`     | The location keeps BunkerWeb's checks. Mount the file into the BunkerWeb container. Match Apache's path rule exactly: see the `/admin` trap.                                                                                                                                                     |
| `Require ip` / `Require all denied`, whole vhost   | `GREYLIST_IP` with `USE_GREYLIST=yes` (admit only these); `BLACKLIST_IP` (block these)                            | `WHITELIST_IP` exempts from checks; it does not restrict.                                                                                                                                                                                                                                        |
| `RemoteIPHeader`, `RemoteIPInternalProxy`          | `USE_REAL_IP=yes`, `REAL_IP_HEADER`, `REAL_IP_FROM`                                                               | Needed for any IP rule behind a load balancer or CDN. The default `REAL_IP_FROM` is the three private ranges; write your own.                                                                                                                                                                    |
| `RewriteRule ... [R=301]`, `Redirect permanent`    | `REDIRECT_FROM`, `REDIRECT_TO`, `REDIRECT_TO_REQUEST_URI`, `REDIRECT_TO_STATUS_CODE`                              | One numbered group per redirect. `REDIRECT_FROM` is an nginx prefix unless it starts with `^` or ends with `$`.                                                                                                                                                                                  |
| `RewriteRule` that rewrites internally             | regex `REVERSE_PROXY_URL_<n>` and a capture in `REVERSE_PROXY_HOST_<n>`, when equivalent                          | An nginx URI rewrite in a location include or `server-http` marks requests internal and skips BunkerWeb's Lua checks; ModSecurity still runs. If no regex-and-capture form fits, list it as "not carried over", or retain it with that warning. Test bare paths, encoded characters and queries. |
| `SSLCertificateFile`, `SSLCertificateKeyFile`      | `USE_CUSTOM_SSL=yes`, `CUSTOM_SSL_CERT`, `CUSTOM_SSL_KEY`, or `AUTO_LETS_ENCRYPT=yes`                             | Paths readable by the **scheduler**. Put the chain (`SSLCertificateChainFile`) in the certificate file. Without a source, HTTPS answers with a placeholder certificate.                                                                                                                          |
| `SSLProtocol`, `SSLCipherSuite`                    | `SSL_PROTOCOLS`, `SSL_CIPHERS_LEVEL`, `SSL_CIPHERS_CUSTOM`                                                        | Defaults `TLSv1.2 TLSv1.3` and `modern`.                                                                                                                                                                                                                                                         |
| `Redirect` or `RewriteRule` from HTTP to HTTPS     | `REDIRECT_HTTP_TO_HTTPS=yes`                                                                                      | `AUTO_REDIRECT_HTTP_TO_HTTPS` (default `yes`) already redirects once a certificate source exists.                                                                                                                                                                                                |
| `Timeout`, `ProxyTimeout`                          | `REVERSE_PROXY_CONNECT_TIMEOUT[_n]`, `REVERSE_PROXY_READ_TIMEOUT[_n]`, `REVERSE_PROXY_SEND_TIMEOUT[_n]`           | Default `60s` each, per location. Not exercised live.                                                                                                                                                                                                                                            |
| `KeepAliveTimeout`, `RequestReadTimeout`           | `KEEPALIVE_TIMEOUT`, `CLIENT_HEADER_TIMEOUT`, `CLIENT_BODY_TIMEOUT`, `SEND_TIMEOUT`                               | Global settings (15s, 10s, 10s, 10s): they apply to every service on the instance, not per vhost. Not exercised live.                                                                                                                                                                            |
| `AuthType Basic`, `AuthUserFile`                   | `USE_AUTH_BASIC=yes`, `AUTH_BASIC_LOCATION`, `AUTH_BASIC_USER[_n]`, `AUTH_BASIC_PASSWORD[_n]`                     | `.htpasswd` hashes cannot be imported; users need new passwords.                                                                                                                                                                                                                                 |
| `ErrorDocument`                                    | `ERRORS`, `INTERCEPTED_ERROR_CODES`                                                                               |                                                                                                                                                                                                                                                                                                  |
| `DocumentRoot`, `Alias`                            | `SERVE_FILES=yes`, `ROOT_FOLDER`                                                                                  |                                                                                                                                                                                                                                                                                                  |
| `mod_deflate`                                      | `USE_GZIP=yes`, `USE_BROTLI=yes`                                                                                  | Both default to `no`.                                                                                                                                                                                                                                                                            |
| `ProxyPassMatch`, `<LocationMatch>`                | `REVERSE_PROXY_URL_<n>` that starts with `^`, ends with `$`, or begins with a `~ `, `~* `, `= ` or `^~ ` modifier | A regex URL wins over the `/` entry.                                                                                                                                                                                                                                                             |
| `<Proxy balancer://...>`, `BalancerMember`         | no core setting                                                                                                   | `REVERSE_PROXY_HOST` takes one target. Options: the BunkerWeb PRO Load Balancer plugin, or a balancer in front of the replicas.                                                                                                                                                                  |
| `ProxyPassMatch ... fcgi://` (PHP-FPM)             | `REMOTE_PHP`, `REMOTE_PHP_PORT`, `REMOTE_PHP_PATH`                                                                |                                                                                                                                                                                                                                                                                                  |

## Needs a custom config

For `Rewrite*` logic with no regex-and-capture equivalent, list it as "not carried over", or retain an nginx URI rewrite only with the Lua-check bypass warning above. `SetEnvIf` and other logic with no setting above, `<If>` expressions, `mod_security` rules and anything at server level go in `server-http`, or an include file inside one proxied location. Rules from `mod_security` follow [`bunkerweb-migrate-modsecurity`](https://github.com/bunkerity/bunkerweb-skills/tree/main/skills/bunkerweb-migrate-modsecurity). Types and where the files go: "Custom config types" in `SKILL.md`. `.htaccess` files have no equivalent: list every directive found in them, because nothing reads them after cutover.
