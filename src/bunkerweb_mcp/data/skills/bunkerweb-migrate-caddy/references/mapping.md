# Mapping: Caddy to BunkerWeb

Verified at BunkerWeb v1.6.15 for every BunkerWeb name. Caddyfile directive names are Caddy's: check them against the user's Caddy version (for example `basicauth` became `basic_auth` in 2.8). Per-service settings are `<server_name>_<SETTING>` with `MULTISITE=yes`, or `bunkerweb.<SETTING>` labels with autoconf. The [`bunkerweb-migrate-nginx`](https://github.com/bunkerity/bunkerweb-skills/tree/main/skills/bunkerweb-migrate-nginx) skill covers the settings named here in more detail.

## Mapping

| Caddyfile                                                               | BunkerWeb                                                                                                                                                                | Notes                                                                                                                                                                                                                                                                                    |
| ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| site address `app.example.com`                                          | `SERVER_NAME`                                                                                                                                                            | Several addresses in one block: space-separated. A port in the address maps to the published port, not to a setting.                                                                                                                                                                     |
| automatic HTTPS                                                         | `AUTO_LETS_ENCRYPT=yes`, `EMAIL_LETS_ENCRYPT`                                                                                                                            | Caddy does it by default; BunkerWeb does not. See the traps in `SKILL.md`.                                                                                                                                                                                                               |
| HTTP to HTTPS redirect (automatic)                                      | `AUTO_REDIRECT_HTTP_TO_HTTPS` (default `yes`, applies once a certificate is configured), or `REDIRECT_HTTP_TO_HTTPS=yes`                                                 | Caddy answers `308`, BunkerWeb `301`. Same target, different code; caches and tools that care about the method see it. Verified live.                                                                                                                                                    |
| `tls <cert> <key>`, and Caddy's stored certificates                     | `USE_CUSTOM_SSL=yes`, `CUSTOM_SSL_CERT`, `CUSTOM_SSL_KEY`                                                                                                                | Files must be mounted into the scheduler and readable by it (it runs as uid 101; Caddy's copies are mode `0600` root). Verified live: the served certificate matched the Caddy file.                                                                                                     |
| `tls internal`                                                          | `GENERATE_SELF_SIGNED_SSL=yes`                                                                                                                                           | Self-signed, not a local CA. Clients that trusted Caddy's root will not trust it. Caddy's own `local` certificates last 12 hours.                                                                                                                                                        |
| `tls { dns <provider> }`, wildcard                                      | `LETS_ENCRYPT_CHALLENGE=dns`, `LETS_ENCRYPT_DNS_PROVIDER`, `LETS_ENCRYPT_DNS_CREDENTIAL_ITEM`, `USE_LETS_ENCRYPT_WILDCARD`                                               | Provider coverage differs from Caddy's modules: check the provider is supported.                                                                                                                                                                                                         |
| ZeroSSL issuer (Caddy's fallback)                                       | `LETS_ENCRYPT_SERVER=zerossl`, `LETS_ENCRYPT_ZEROSSL_API_KEY`                                                                                                            | `LETS_ENCRYPT_SERVER` is `letsencrypt` or `zerossl`.                                                                                                                                                                                                                                     |
| `reverse_proxy host:port`                                               | `USE_REVERSE_PROXY=yes`, `REVERSE_PROXY_HOST=http://host:port`                                                                                                           | Caddy defaults the scheme to `http`; BunkerWeb needs it written. Several upstreams: no core setting (see below).                                                                                                                                                                         |
| `reverse_proxy https://host`                                            | `REVERSE_PROXY_HOST=https://host`, `REVERSE_PROXY_SSL_SNI`, `REVERSE_PROXY_SSL_VERIFY`                                                                                   | Verification is off by default, the opposite of what a careful Caddyfile does. Turn it on and give a CA with `REVERSE_PROXY_SSL_TRUSTED_CERTIFICATE`.                                                                                                                                    |
| `handle /path*`, `route`, `@matcher path`                               | numbered `REVERSE_PROXY_URL_<n>` and `REVERSE_PROXY_HOST_<n>`                                                                                                            | Each matcher that proxies is one pair.                                                                                                                                                                                                                                                   |
| `handle_path /api/*`, `uri strip_prefix`                                | `REVERSE_PROXY_URL_<n>=^/api/(.*)$`, `REVERSE_PROXY_HOST_<n>=http://app:3000/$1$is_args$args`                                                                            | Live for ordinary paths and queries. Encoded `%2F` differs: Caddy preserves it, the capture decodes it to `/`. Bare `/api` and `/apix` need the unstripped fallback. See the observed edge cases below. In compose, write each `$` as `$$`.                                              |
| websockets (automatic)                                                  | `REVERSE_PROXY_WS=yes` (per location: `_<n>`)                                                                                                                            | Caddy upgrades connections without a flag; BunkerWeb needs it. Caddy has no idle limit; BunkerWeb closes an idle websocket at `REVERSE_PROXY_READ_TIMEOUT` (60 s default, verified live): raise it on that entry.                                                                        |
| `header_up Name value`                                                  | `REVERSE_PROXY_HEADERS=Name value;Other value`                                                                                                                           | Replaces BunkerWeb's default of the same name.                                                                                                                                                                                                                                           |
| `header Name value` (response)                                          | `CUSTOM_HEADER_<n>=Name: value`, or `REVERSE_PROXY_HEADERS_CLIENT`                                                                                                       | Managed headers have their own settings: `STRICT_TRANSPORT_SECURITY`, `CONTENT_SECURITY_POLICY`, `X_FRAME_OPTIONS` (default `SAMEORIGIN`, so `DENY` must be set). `STRICT_TRANSPORT_SECURITY` is sent on HTTPS only, Caddy's `header` also answers on HTTP. Verified live.               |
| `header -Server`, `-X-Powered-By`                                       | `REMOVE_HEADERS`                                                                                                                                                         | The default already removes `Server`, `X-Powered-By` and a few others.                                                                                                                                                                                                                   |
| `encode gzip zstd`                                                      | `USE_GZIP=yes`, `USE_BROTLI=yes`                                                                                                                                         | No zstd setting in core. Verified live for gzip: both answer `Content-Encoding: gzip` on a body above BunkerWeb's `GZIP_MIN_LENGTH` (1000 bytes).                                                                                                                                        |
| `basic_auth /secure*`                                                   | `USE_AUTH_BASIC=yes`, `AUTH_BASIC_LOCATION=/secure`, `AUTH_BASIC_USER`, `AUTH_BASIC_PASSWORD` (more users: `_2`, `_3`, ...)                                              | Caddy stores bcrypt hashes; the setting takes the plain-text password. Users need new passwords. `AUTH_BASIC_LOCATION` is a prefix match. Not enforced in detect mode (verified live): test it in block mode.                                                                            |
| `@internal not client_ip 10.0.0.0/8` or `remote_ip`, plus `respond 403` | `USE_GREYLIST=yes` with `GREYLIST_IP` (site-wide); `BLACKLIST_IP`; one path: a numbered `REVERSE_PROXY_URL_<n>` with `REVERSE_PROXY_INCLUDES_<n>` holding `allow`/`deny` | `WHITELIST_IP` exempts from checks; it does not restrict. `client_ip` follows `trusted_proxies` and so matches BunkerWeb with `USE_REAL_IP=yes` (verified live). `remote_ip` is the TCP peer and ignores `X-Forwarded-For`: there is no equivalent while `USE_REAL_IP=yes`; say so.      |
| `request_body { max_size 50MB }`                                        | `MAX_CLIENT_SIZE=50000000`                                                                                                                                               | Caddy's `MB` is decimal (`50MB` is 50,000,000 bytes; `50MiB` is binary), nginx's `50m` is binary. The setting takes a plain byte count; default `10m`. Verified live: `5m` let a 5.1 MB body through where Caddy refused it.                                                             |
| `redir /old /new 301`, `redir https://other{uri}`                       | `REDIRECT_FROM`, `REDIRECT_TO`, `REDIRECT_TO_REQUEST_URI=yes` for `{uri}`, `REDIRECT_TO_STATUS_CODE`                                                                     | One numbered group per redirect. `redir` without a code is `302` (`caddy adapt` shows it), BunkerWeb defaults to `301`: write the code. `redir /old` matches that path only; a plain `REDIRECT_FROM=/old` is an nginx prefix and also redirects `/older`. Write `^/old$`. Verified live. |
| `file_server`, `root *`                                                 | `SERVE_FILES=yes`, `ROOT_FOLDER`                                                                                                                                         |                                                                                                                                                                                                                                                                                          |
| `php_fastcgi host:9000`                                                 | `REMOTE_PHP`, `REMOTE_PHP_PORT`, `REMOTE_PHP_PATH`                                                                                                                       |                                                                                                                                                                                                                                                                                          |
| `rate_limit` (third-party module, `events 3`, `window 1m`)              | `USE_LIMIT_REQ`, `LIMIT_REQ_URL_<n>=^/login$`, `LIMIT_REQ_RATE_<n>=3r/m`                                                                                                 | Rate format `3r/m`. Verified live: same 200, 200, 200, 429 sequence. Caddy adds `Retry-After`, BunkerWeb does not. Stock Caddy has no limiter, so every converted site gains BunkerWeb's default `2r/s`.                                                                                 |
| HTTP/3 (on by default)                                                  | `HTTP3` (default `yes`)                                                                                                                                                  | Publish `443:8443/udp` as well as TCP.                                                                                                                                                                                                                                                   |
| unknown `Host` (a host-matched site)                                    | `DISABLE_DEFAULT_SERVER=yes`                                                                                                                                             | Caddy answers an empty `200`; BunkerWeb answers `403` with the setting (default `no`). Verified live.                                                                                                                                                                                    |
| `trusted_proxies`                                                       | `USE_REAL_IP=yes`, `REAL_IP_FROM`, `REAL_IP_HEADER`                                                                                                                      | Needed behind a CDN or another proxy. `private_ranges` is the default `REAL_IP_FROM`.                                                                                                                                                                                                    |

## Needs a custom config

Global options (the `{ ... }` block), `import` snippets, `map`, CEL or named-matcher logic with no setting above, and `respond` handlers go in `server-http` (server level) or an include file (inside one proxied location). `respond` and `redir` blocks written as nginx `return` skip BunkerWeb's access-phase checks, so tell the user. Types and where to put the files: "Custom config types" in `SKILL.md`.

## Observed prefix edge cases

The ordinary deep path and query matched. Bare `/api` and `/apix` went to the unstripped fallback; `/api/` became `/`. Caddy preserved `%2F` in `/api/a%2Fb`, while the regex capture sent `/a/b`: this form does **not** preserve Caddy's encoded-slash semantics. Space and UTF-8 encodings matched the upstream request line; doubled slashes became `/x` on both. `/api/../admin`, sent with `curl --path-as-is`, bypassed the stripping match on both and reached the fallback with its original request line. Keep the fallback and its controls; do not treat this as an ACL parity test. If the application distinguishes encoded slashes, mark that behavior as not carried over and resolve it before cutover; do not restore a URI rewrite to hide the mismatch. See [verified-live.md](verified-live.md) for the request tables and Lua/CRS proof.
