# Mapping: nginx to BunkerWeb

Verified at BunkerWeb v1.6.15. Setting names come from `src/common/core/<plugin>/plugin.json`. In multisite mode (`MULTISITE=yes`, needed for autoconf) write per-service settings as `<server_name>_<SETTING>`; with autoconf labels use `bunkerweb.<SETTING>` on the application container.

Rows that say "verified live" were run against nginx 1.30.5 and BunkerWeb 1.6.15, see [verified-live.md](verified-live.md). The others come from the setting definitions.

## Mapping

| `server_name`                                            | `SERVER_NAME`                                                                                                                                | Space-separated. The first name is the primary one and the prefix for multisite settings.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `listen 80` / `listen 443 ssl`                           | published ports `80:8080` and `443:8443`                                                                                                     | BunkerWeb listens on `HTTP_PORT=8080` and `HTTPS_PORT=8443` inside its container. Without a certificate source, HTTPS answers with BunkerWeb's default placeholder certificate and browsers warn.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `ssl_protocols`                                          | `SSL_PROTOCOLS`                                                                                                                              | Default `TLSv1.2 TLSv1.3`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `ssl_ciphers`                                            | `SSL_CIPHERS_LEVEL` (`modern` default), `SSL_CIPHERS_CUSTOM`                                                                                 | A custom string overrides the level.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `return 301 https://$host$request_uri`                   | `REDIRECT_HTTP_TO_HTTPS=yes`                                                                                                                 | `AUTO_REDIRECT_HTTP_TO_HTTPS` already redirects when HTTPS is detected.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `return 301 <url>`, whole site or one `location`         | `REDIRECT_TO`, `REDIRECT_TO_REQUEST_URI`, `REDIRECT_TO_STATUS_CODE`                                                                          | `REDIRECT_FROM` (default `/`) picks the path: a prefix, or a regex when it starts with `^` (`^/old$` for `location = /old`). `REDIRECT_TO_REQUEST_URI=yes` appends the request path and query (`return 301 https://example.org$request_uri`). The four are one numbered group. Verified live.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `client_max_body_size`                                   | `MAX_CLIENT_SIZE` (default `10m`); one location: `REVERSE_PROXY_MAX_CLIENT_SIZE[_n]`                                                         | Set it, or large uploads fail with 413. A per-location size beats the server one both ways (verified live: 6 MiB passed a `20m` location under a `5m` server). In block mode a body that is not a file upload is also capped by `MODSECURITY_REQ_BODY_NO_FILES_LIMIT` (default 131072): a 4 MiB form post got 400 until it was raised.                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `proxy_pass http://host:port`                            | `USE_REVERSE_PROXY=yes`, `REVERSE_PROXY_HOST=http://host:port`                                                                               | Full URL with scheme, no path. `proxy_pass http://host/v2/` on a `location /api/` does not carry over. Say in the answer that a path in the host replaces the whole request URI, query string included (verified live). Use `REVERSE_PROXY_URL_<n>=^/api/(.*)$` with `REVERSE_PROXY_HOST_<n>=http://app:3000/v2/$1$is_args$args`. A URI rewrite in an include marks requests internal and skips BunkerWeb's Lua checks. The regex form was run live: preserve the separate bare `/api` redirect and destination controls; see the edge cases below. In compose, write each `$` as `$$`.                                                                                                                                                                                                              |
| `location /path`                                         | `REVERSE_PROXY_URL` and `REVERSE_PROXY_HOST`, then `_2`, `_3` for more                                                                       | Each pair is one generated `location`. `REVERSE_PROXY_URL` defaults to `/`; set it on every numbered entry or it falls back to `/`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `location ~ regex`, `= /x`, `^~ /x`                      | `REVERSE_PROXY_URL=~ regex`, or start with `^` / end with `$`                                                                                | Only `^`, `$`, or an explicit `~`, `~*`, `=`, `^~` modifier changes the match; anything else is a literal prefix.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `proxy_http_version 1.1` plus `Upgrade` header           | `REVERSE_PROXY_WS[_n]=yes`                                                                                                                   | Per location. It sets the version and both headers. Do not repeat them in `REVERSE_PROXY_HEADERS`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `proxy_set_header Name value`                            | `REVERSE_PROXY_HEADERS[_n]`, entries `Name value` separated by `;`                                                                           | An entry replaces BunkerWeb's default of the same name (`Host`, `X-Forwarded-For`, `X-Real-IP`, `X-Forwarded-Proto`). `REVERSE_PROXY_CUSTOM_HOST` overrides `Host` service-wide. A server-level `proxy_set_header` does not reach a generated location (verified live): repeat it in `REVERSE_PROXY_HEADERS` of every entry that inherited it in nginx. The value may use an nginx variable defined by a `map`, written `$$name` in a compose file. A site with no `proxy_set_header` at all sent `Host: <upstream>` from nginx, while BunkerWeb sends the requested name plus `X-Forwarded-*` and `X-Real-IP` headers.                                                                                                                                                                              |
| `proxy_hide_header`                                      | `REVERSE_PROXY_HIDE_HEADERS[_n]`                                                                                                             | Defaults to `Upgrade`. Setting it replaces that default.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `add_header` on a proxied location                       | `REVERSE_PROXY_HEADERS_CLIENT[_n]`, or `CUSTOM_HEADER_<n>` (`Name: value`)                                                                   | For headers BunkerWeb already manages, use the managed setting instead (below). `always` has no equivalent to set: managed and custom headers are also sent on 403 answers (verified live).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| HSTS, CSP, frame, referrer, permissions headers          | `STRICT_TRANSPORT_SECURITY`, `CONTENT_SECURITY_POLICY`, `X_FRAME_OPTIONS`, `REFERRER_POLICY`, `PERMISSIONS_POLICY`, `X_CONTENT_TYPE_OPTIONS` | They ship with non-empty defaults. A raw `add_header` for one of them makes the client receive two copies (verified live with `X-Frame-Options`: `SAMEORIGIN` and `DENY`). HSTS default is `max-age=63072000; includeSubDomains; preload`: set your old value explicitly. BunkerWeb sends HSTS only over HTTPS, nginx's `add_header ... always` also on HTTP.                                                                                                                                                                                                                                                                                                                                                                                                                                        |

| `proxy_buffering`, `proxy_request_buffering`             | `REVERSE_PROXY_BUFFERING[_n]`, `REVERSE_PROXY_REQUEST_BUFFERING[_n]`                                                                         | Request buffering stays on while ModSecurity inspects that location. `REVERSE_PROXY_BUFFERING=no` matched `proxy_buffering off` (verified live over HTTPS, where a chunked reply started after 2 s against 4 s buffered).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |

| `limit_req`, `limit_req_zone`                            | `USE_LIMIT_REQ`, `LIMIT_REQ_URL_<n>`, `LIMIT_REQ_RATE_<n>` (`2r/s`, `30r/m`)                                                                 | BunkerWeb counts in Lua with a sliding window, and has no `burst`: `rate=3r/m burst=2` and `3r/m` both admitted three requests and refused the next ones, but nginx earned a request back after 20 s and BunkerWeb waited out the window (verified live). ## Observed prefix edge cases

The deep path and query, trailing slash, `/apix`, encoded slash, space, UTF-8 and doubled slash matched. nginx decoded `%2F` to `/` before prefix replacement, and the capture did the same. Bare `/api` was a source `301` to `/api/`, while the initial regex fell through to the unstripped fallback. A separate `REDIRECT_FROM=^/api$`, `REDIRECT_TO=http://nginx.example.com/api/$is_args$args`, `REDIRECT_TO_STATUS_CODE=301` matched the source over HTTP, including `/api?q=1&r=a%20b`; use the served name and intended scheme, and verify HTTPS separately. This fixed target does not establish dynamic scheme or Host parity. `/api/../admin`, sent with `curl --path-as-is`, selected the fallback and preserved its original upstream request line in this prefix-only conversion. Carry any controls on the normalized destination separately. In compose, escape every `$` as `$$`. See [verified-live.md](verified-live.md) for the request tables and Lua/CRS proof.
