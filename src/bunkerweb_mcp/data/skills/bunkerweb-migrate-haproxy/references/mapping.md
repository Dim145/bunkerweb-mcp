# Mapping: HAProxy to BunkerWeb

Verified at BunkerWeb v1.6.15 for every BunkerWeb name. Keyword names are HAProxy's: check them against the user's HAProxy version. Per-service settings are `<server_name>_<SETTING>` with `MULTISITE=yes`, or `bunkerweb.<SETTING>` labels with autoconf. The [`bunkerweb-migrate-nginx`](https://github.com/bunkerity/bunkerweb-skills/tree/main/skills/bunkerweb-migrate-nginx) skill maps the shared settings in more detail.

HAProxy sits at layer 4 and 7 and BunkerWeb is a layer 7 reverse proxy with a WAF. Map the HTTP frontends. A `mode tcp` frontend becomes a stream service (`SERVER_TYPE=stream`, `LISTEN_STREAM_PORT`, `REVERSE_PROXY_HOST`), and BunkerWeb's WAF does not see that traffic.

## Mapping

| HAProxy                                                             | BunkerWeb                                                                                                                    | Notes                                                                                                                                                                                                                                       |
| ------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `frontend` with `acl ... hdr(host)` and `use_backend`               | one `SERVER_NAME` entry per host                                                                                             | The first name is the multisite prefix. A host with no matching `use_backend` and no `default_backend` is what `DISABLE_DEFAULT_SERVER=yes` covers; see the traps.                                                                          |
| `backend` with one `server host:port`                               | `USE_REVERSE_PROXY=yes`, `REVERSE_PROXY_HOST=http://host:port`                                                               | Scheme required, no path. `use_backend` rules on a path become numbered `REVERSE_PROXY_URL_<n>` and `REVERSE_PROXY_HOST_<n>` pairs.                                                                                                         |
| `backend` with several `server` lines, `balance`, health check      | no core setting                                                                                                              | `REVERSE_PROXY_HOST` takes one target. Options: the BunkerWeb PRO Load Balancer plugin, or keep a balancer in front of the replicas.                                                                                                        |
| `bind :80`, `bind :443 ssl`                                         | published ports `80:8080` and `443:8443`                                                                                     | BunkerWeb listens on 8080 and 8443 inside its container.                                                                                                                                                                                    |
| `bind ... ssl crt /path/site.pem`                                   | `USE_CUSTOM_SSL=yes`, `CUSTOM_SSL_CERT`, `CUSTOM_SSL_KEY`, or `AUTO_LETS_ENCRYPT=yes`                                        | A HAProxy `.pem` bundles certificate, chain and key in one file; BunkerWeb wants the key apart. Split it. Paths readable by the **scheduler**.                                                                                              |
| `ssl-min-ver`, `ciphers`, `ciphersuites`, `alpn h2`                 | `SSL_PROTOCOLS`, `SSL_CIPHERS_LEVEL`, `SSL_CIPHERS_CUSTOM`, `HTTP2`                                                          | Defaults `TLSv1.2 TLSv1.3`, `modern`, `HTTP2=yes`.                                                                                                                                                                                          |
| `http-request redirect scheme https`                                | `REDIRECT_HTTP_TO_HTTPS=yes`                                                                                                 | `AUTO_REDIRECT_HTTP_TO_HTTPS` (default `yes`) already redirects once a certificate source exists.                                                                                                                                           |
| `http-request redirect location <url> code 301 if <acl>`            | `REDIRECT_FROM`, `REDIRECT_TO`, `REDIRECT_TO_REQUEST_URI`, `REDIRECT_TO_STATUS_CODE`                                         | One numbered group per redirect. `REDIRECT_FROM` is an nginx prefix unless it starts with `^` or ends with `$`.                                                                                                                             |
| `http-request deny if { path_beg /admin } !{ src <cidr> }`          | a numbered entry plus `REVERSE_PROXY_INCLUDES_<n>=/path/acl.conf` holding `allow <cidr>;` and `deny all;`                    | The location keeps BunkerWeb's checks. Mount the file into the BunkerWeb container. Whole site: `GREYLIST_IP` with `USE_GREYLIST=yes` (admit only these), or `BLACKLIST_IP`.                                                                |
| `http-request deny if { src -f deny.lst }`                          | `BLACKLIST_IP`, or `BLACKLIST_IP_URLS` for a list fetched from a URL                                                         | `WHITELIST_IP` exempts from checks; it does not restrict.                                                                                                                                                                                   |
| `http-request deny deny_status 413 if` on `content-length`          | `MAX_CLIENT_SIZE=5m` (default `10m`); one location: `REVERSE_PROXY_MAX_CLIENT_SIZE[_n]`                                      | nginx counts the bytes it receives, so chunked bodies no longer slip past a `content-length` test.                                                                                                                                          |
| `http-request set-src hdr(x-forwarded-for) if { src <cidr> }`       | `USE_REAL_IP=yes`, `REAL_IP_HEADER`, `REAL_IP_FROM`                                                                          | Needed for any IP rule behind a load balancer or CDN. The default `REAL_IP_FROM` is the three private ranges; write your own.                                                                                                               |
| `bind ... accept-proxy`                                             | `USE_PROXY_PROTOCOL=yes`                                                                                                     | A global setting: it applies to every service on the instance.                                                                                                                                                                              |
| `option forwardfor`                                                 | default                                                                                                                      | BunkerWeb sends `X-Forwarded-For` (client address appended to the incoming chain), `X-Real-IP`, `X-Forwarded-Proto`, `X-Forwarded-Host` and `Host` without any setting, plus `X-Forwarded-Prefix` for a non-regex URL that starts with `/`. |
| `http-request set-header Name value`                                | `REVERSE_PROXY_HEADERS[_n]=Name value;Other value`                                                                           | Per location. An entry replaces BunkerWeb's default of the same name.                                                                                                                                                                       |
| `http-response set-header Strict-Transport-Security ...`            | `STRICT_TRANSPORT_SECURITY=max-age=31536000; includeSubDomains`                                                              | Sent on HTTPS responses only; HAProxy sent it on HTTP too. The default is `max-age=63072000; includeSubDomains; preload`, so set your own value.                                                                                            |
| `http-response set-header` for CSP, frame, referrer                 | `CONTENT_SECURITY_POLICY`, `X_FRAME_OPTIONS`, `REFERRER_POLICY`, `PERMISSIONS_POLICY`, `X_CONTENT_TYPE_OPTIONS`              | All ship with non-empty defaults. Any other response header: `CUSTOM_HEADER_<n>=Name: value`.                                                                                                                                               |
| `http-response del-header Server`                                   | `REMOVE_HEADERS`                                                                                                             | The default already strips `Server`, `X-Powered-By` and a few more.                                                                                                                                                                         |
| `stick-table` with `http_req_rate`, then `deny_status 429`          | `USE_LIMIT_REQ=yes`, `LIMIT_REQ_URL_<n>`, `LIMIT_REQ_RATE_<n>`                                                               | Rate format `3r/m`, `2r/s`. `LIMIT_REQ_URL` is an unanchored regex: write `^/login$`. A tracked path needs its own numbered pair, see the traps.                                                                                            |
| `stick-table` with `conn_cur`, `maxconn` per source                 | `USE_LIMIT_CONN`, `LIMIT_CONN_MAX_HTTP1`, `LIMIT_CONN_MAX_HTTP2`                                                             | On by default (10 and 100).                                                                                                                                                                                                                 |
| websocket (no flag, `timeout tunnel`)                               | `REVERSE_PROXY_WS_<n>=yes` on the websocket location, and `REVERSE_PROXY_READ_TIMEOUT_<n>`, `REVERSE_PROXY_SEND_TIMEOUT_<n>` | `timeout tunnel` has no direct setting. The idle limit of an open socket is the location's read timeout, `60s` by default. Set it to the old tunnel value on that location.                                                                 |
| `timeout connect`, `timeout server`                                 | `REVERSE_PROXY_CONNECT_TIMEOUT[_n]`, `REVERSE_PROXY_READ_TIMEOUT[_n]`, `REVERSE_PROXY_SEND_TIMEOUT[_n]`                      | Default `60s` each, per location.                                                                                                                                                                                                           |
| `timeout client`, `timeout http-request`, `timeout http-keep-alive` | `CLIENT_HEADER_TIMEOUT`, `CLIENT_BODY_TIMEOUT`, `SEND_TIMEOUT`, `KEEPALIVE_TIMEOUT`                                          | Global settings (10s, 10s, 10s, 15s): they apply to every service on the instance, not per site. Not exercised live.                                                                                                                        |
| `userlist`, `http-request auth`                                     | `USE_AUTH_BASIC=yes`, `AUTH_BASIC_LOCATION`, `AUTH_BASIC_USER[_n]`, `AUTH_BASIC_PASSWORD[_n]`                                | The setting takes plain-text passwords; HAProxy's hashes cannot be imported.                                                                                                                                                                |
| `compression algo gzip`                                             | `USE_GZIP=yes`, `USE_BROTLI=yes`                                                                                             | Both default to `no`.                                                                                                                                                                                                                       |
| `errorfile 503 /path`                                               | `ERRORS`, `INTERCEPTED_ERROR_CODES`                                                                                          |                                                                                                                                                                                                                                             |

## Needs a custom config

Map `http-request` path changes (`set-path`, `replace-path`) to a regex `REVERSE_PROXY_URL_<n>` and a capture in `REVERSE_PROXY_HOST_<n>` when equivalent; preserve the query with `$is_args$args`. Test bare paths, encoded characters and queries; in compose, write each `$` as `$$`. Path or query changes with no equivalent are "not carried over", or retained only with this warning: an nginx URI rewrite in `server-http` or a location include marks requests internal and skips BunkerWeb's Lua checks; ModSecurity still runs. `map` files, Lua actions, `http-request lua.*`, SPOE and any logic with no setting above go in `server-http`, or an include file inside one proxied location. Types and where the files go: "Custom config types" in `SKILL.md`.
