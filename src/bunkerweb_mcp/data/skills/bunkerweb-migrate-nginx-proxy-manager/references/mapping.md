# Mapping: Nginx Proxy Manager to BunkerWeb

BunkerWeb names are verified at v1.6.15. Every row marked "Live" was run side by side against Nginx Proxy Manager (NPM) 2.16.0: see [verified-live.md](verified-live.md). NPM field names come from its own API schema (`/api/schema`) and its generated files. In multisite mode write per-service settings as `<server_name>_<SETTING>`; with autoconf they are `bunkerweb.<SETTING>` labels on the application container. Raw nginx text from the Advanced tab goes through [`bunkerweb-migrate-nginx`](https://github.com/bunkerity/bunkerweb-skills/tree/main/skills/bunkerweb-migrate-nginx).

## What "Block Common Exploits" leaves open

NPM's snippet (`conf.d/include/block-exploits.conf`) tests the raw query string and nine user agents, then returns 403. In `block` mode with the defaults, CRS answered 403 for a script tag, `union select version()` and `/proc/self/environ`, and also for two payloads NPM let through (`' OR '1'='1` and a Log4Shell string). It answered 200 for the `libwww-perl` agent and for `GLOBALS[a]=1`. Carry those two over with these, both live:

```text
<server>_BLACKLIST_USER_AGENT=(?:Indy Library|libwww-perl|GetRight|GetWeb!|Go!Zilla|Download Demon|Go-Ahead-Got-It|TurnitinBot|GrabNet)
<server>_CUSTOM_CONF_MODSEC_CRS_npm-exploits=SecRule QUERY_STRING "@rx (?i)(GLOBALS|_REQUEST)(=|\[|%[0-9A-Z]{0,2})" "id:1000901,phase:2,deny,status:403,log,msg:npm-globals-request"
```

The other query patterns in the snippet (`base64_decode(`, `mosConfig_`, spam words) were not each tested.

## Hosts as settings

Five proxy hosts become one `SERVER_NAME` list and five groups, each prefixed with the host's first domain name. This is the live-tested shape for one host with a custom location, an ACL on it, a websocket and a rate limit:

```text
MULTISITE=yes
SERVER_NAME=app1.example.com app2.example.com app3.example.com app4.example.com app5.example.com
USE_REAL_IP=yes
REAL_IP_HEADER=X-Real-IP
app1.example.com_USE_REVERSE_PROXY=yes
app1.example.com_REVERSE_PROXY_URL=/
app1.example.com_REVERSE_PROXY_HOST=http://app1:8080
app1.example.com_REVERSE_PROXY_WS=yes
app1.example.com_REVERSE_PROXY_URL_2=/admin
app1.example.com_REVERSE_PROXY_HOST_2=http://app1:8080
app1.example.com_REVERSE_PROXY_WS_2=yes
app1.example.com_REVERSE_PROXY_INCLUDES_2=/etc/bunkerweb-includes/admin-acl.conf
app1.example.com_LIMIT_REQ_URL_2=^/login
app1.example.com_LIMIT_REQ_RATE_2=3r/m
app1.example.com_SECURITY_MODE=detect
```

Repeat the group for `app2.example.com` to `app5.example.com`. `admin-acl.conf` holds `allow 10.1.2.0/24;` and `deny all;`. Mount it into the BunkerWeb container, not the scheduler. In compose write `$$` for every `$`. With Docker autoconf the same settings are `bunkerweb.<SETTING>` labels on each application container, without the prefix.

## Certificates

You cannot run NPM and BunkerWeb on port 80 together, and the HTTP challenge needs port 80, so BunkerWeb cannot validate while it sits on spare ports. Pick one of these before the parallel run:

- **Reuse NPM's files.** For a custom certificate copy `fullchain.pem` and `privkey.pem` out of `/data/custom_ssl/npm-<id>/`. For a Let's Encrypt one they are under NPM's `/etc/letsencrypt/` folder (`live/npm-<id>/`, from NPM's documentation, not checked here). Put them where the **scheduler** can read them and set `USE_CUSTOM_SSL=yes`, `CUSTOM_SSL_CERT`, `CUSTOM_SSL_KEY`. At cutover switch to `AUTO_LETS_ENCRYPT=yes` and `USE_CUSTOM_SSL=no`.
- **Issue with the DNS challenge.** `LETS_ENCRYPT_CHALLENGE=dns` needs no port 80, so BunkerWeb can hold a trusted certificate before cutover.

Set `EMAIL_LETS_ENCRYPT` for expiry notices: for Let's Encrypt it is optional (without it BunkerWeb logs a warning and registers without a contact address), while ZeroSSL needs it or an API key.

`USE_LETS_ENCRYPT_STAGING=yes` is for rehearsing issuance at the real cutover: it has much higher rate limits and issues untrusted certificates, but it still validates over port 80, so it is no way around the port conflict. Turn it off for cutover.

Let's Encrypt limits new orders per account and certificates per exact domain set and per registered domain (see [the rate-limit page](https://letsencrypt.org/docs/rate-limits/)). Five hosts re-issued in one burst can hit them, and a failed validation counts. Do not delete NPM's certificates until BunkerWeb has issued its own.

## Parallel run and cutover

1. Start BunkerWeb on spare host ports, for example `8081:8080` and `8444:8443`. Not `81`: NPM's admin UI uses it.
2. Create the services with `SECURITY_MODE=detect`. Test each with `curl --resolve <domain>:8444:127.0.0.1 https://<domain>:8444/`. Basic auth and the greylist refuse nothing in `detect` (they log `detected deny access`), so test them in `block` on a spare hostname, or rely on an include-file ACL.
3. Cut over: stop NPM, recreate BunkerWeb with `80:8080` and `443:8443`. Two proxies cannot share the ports, so expect a gap of seconds. Say so; "without downtime" on one host means a restart-sized gap, not none. For none, put the old and new proxy on different host IPs or use a load balancer in front.
4. Rollback: stop BunkerWeb, start NPM again. Keep NPM's containers and volumes intact until the new certificates are issued and a week has passed.

## Observed prefix edge cases

The original `^/api(/.*)?$` missed `/apix`: NPM forwarded it as `/v2x`, while BunkerWeb used the fallback `/apix`. The tested correction `^/api(.*)$` with the same `/v2$1$is_args$args` host expression matched that literal prefix behavior. Bare `/api` became `/v2`, `/api/` became `/v2/`, and the deep path/query, encoded slash, space, UTF-8 and doubled slash matched. Do not add a slash boundary unless changing NPM's behavior is intentional. `/api/../admin`, sent with `curl --path-as-is`, normalized outside the prefix location: NPM's separate `/admin` ACL returned `403`; the prefix-only BunkerWeb fixture used its fallback and returned `200` with the original request line. An allowed-address control on NPM returned `200` with that same original line. Carry the destination ACL and trusted-client rules separately; a matching prefix conversion does not preserve them. In compose, escape every `$` as `$$`. See [verified-live.md](verified-live.md) for the request tables and Lua/CRS proof.
